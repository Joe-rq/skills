# PPT 内容优先方法论

按「先内容，后设计」的顺序，把 AI 做 PPT 的长链拆成可确认的六步。每一步都先让用户确认，再进入下一步；内容未定之前不碰视觉，风格未定之前不碰素材。

## 核心原则

- 人负责判断，AI 负责执行。
- 快不等于对。内容错了，再好看也没用。
- 风格一旦选定就不要反复改。
- 每个素材、图表、动效都要回答：加了之后信息是不是更好懂？

## 适用场景

- 用户说「帮我做 PPT」「规划一个演示」「先内容后设计」
- 有主题或素材，但还没想清楚结构和视觉
- 需要一套可复用的 PPT 工作流程
- 从文章、报告、数据出发，整理成演讲结构

## 不适用场景

- 用户明确要求「一键生成完整 PPTX」→ 改用 `pptx-generator` 或 `frontend-slides`
- 用户已有最终 PPT，只需要改格式/排版
- 纯技术实现或 API 调用需求
- 只需要单页设计，不需要整体流程

## 使用方法

### 基本调用

```bash
/ppt-methodology-coach 帮我做一个关于 AI 编程助手的内部培训 PPT
```

### 附带素材

```bash
/ppt-methodology-coach @article.md
```

### 典型交互流程

```text
用户：帮我做一个季度汇报 PPT
AI：  先确认目的：这份 PPT 是想让观众「理解」业务进展，还是「说服」他们追加预算？
用户：说服追加预算
AI：  好的，这是说服型 PPT。接下来进入 Phase 2，输出逐页文字稿...
```

Skill 会按 Phase 0 → 6 逐步推进，每完成一个阶段都会先等你确认，再进入下一阶段。

## 快速参考

| 阶段 | 核心任务 | 产出物 | 退出标准 |
|------|---------|--------|----------|
| Phase 0 | 判断起点 | 起始状态确认 | 用户确认从哪开始 |
| Phase 1 | 定目的 | 理解型/说服型 + 观众/场景 | 用户确认目的 |
| Phase 2 | 出内容 | 逐页文字稿 | 用户锁定 outline |
| Phase 3 | 定风格 | 3-5 种风格推荐 | 用户锁定风格 |
| Phase 4 | 出初稿 + 三审 | 三审检查清单 | 用户完成检查 |
| Phase 5 | 补素材 | 素材约束清单 | 用户确认素材方案 |
| Phase 6 | 微调输出 | 输出格式建议 | 用户拿到最终方案 |

## 工作流

### Phase 0：判断起点

收到用户请求后，先判断输入状态：

1. **只有主题/想法** → 从 Phase 1 开始
2. **有文章/报告/数据** → 先提取核心论点，再进 Phase 1
3. **有现有 PPT 要优化** → 明确是内容重构还是视觉优化；本 skill 只做内容重构指导
4. **有大纲但缺细节** → 从 Phase 2 补全

**必须问用户的问题：**
- 这份 PPT 想让别人「理解」一件事，还是「说服」别人做决策？
- 观众是谁？在什么场景下看？（线上/线下、时长、设备）

**退出标准：** 明确起点 + 用户确认。

### Phase 1：定目的

把 PPT 目的分为两类：

| 类型 | 核心目标 | 结构重点 | 风格倾向 |
|------|---------|----------|----------|
| 理解型 | 把复杂信息讲清楚 | 层级、逻辑、少文字 | 清晰、克制 |
| 说服型 | 用论据推结论 | 每页指向最终判断 | 有力、可信 |

**必须回答：**
1. 最终想让观众记住什么？
2. 观众当前对该主题的认知水平？
3. 看完 PPT 后希望他们做什么或相信什么？

**退出标准：** 用户明确目的类型 + 一句话核心结论。

### Phase 2：出逐页文字稿

在没有任何颜色、字体、图片干扰的情况下，先输出纯文字大纲。

**每页必须包含：**
- 标题
- 核心文字（1-3 句话，或 3-5 个要点）
- 与下一页的衔接逻辑

**格式示例：**

```markdown
## Slide 1：封面
- 标题：[一句话标题]
- 副标题：[补充说明]

## Slide 2：问题背景
- 核心信息：[一句话]
- 衔接：由此引出 Slide 3 的解决方案
```

**约束：**
- 每页只讲一个核心点
- 总页数先不急着定，先保证内容成立
- 不要写设计说明（如「这里放一张图」）

**退出标准：** 用户确认「内容本身站得住」，并明确锁定 outline。

> ⚠️ **门控：** outline 锁定前，不进入 Phase 3。

### Phase 3：定视觉风格

基于主题、观众、目的，推荐 3-5 种艺术视觉风格。不要抽象地问「你想要什么风格？」，而是用具体标签 + 一句话描述。

**推荐示例：**
- 瑞士国际主义：网格、留白、无衬线，适合数据与逻辑
- 玻璃拟态：通透、层次、科技感，适合产品与未来主题
- 新粗野主义：大字体、高对比、raw，适合观点鲜明的说服型
- 极简手绘：亲和、非正式，适合教育与内部汇报
- 赛博朋克：霓虹、深色、未来，适合科技/游戏主题

**必须给出：**
- 风格名称
- 适合本主题的理由
- 不适合的风险
- 字体、配色、图片调性的整体方向

**风格报告格式示例：**

```markdown
## 推荐风格 A：瑞士国际主义
- 适合理由：主题涉及大量流程与数据，网格系统能强化逻辑感
- 风险：可能显得过于冷静，缺乏情绪感染力
- 字体：标题用 Helvetica Bold，正文用 PingFang SC
- 配色：主色 #1A1A1A、辅色 #E5E5E5、强调色 #FF4D4F
- 图片调性：高清实拍、留白多、无复杂滤镜
```

**退出标准：** 用户选定一种风格，并承诺后续不再反复改。

> ⚠️ **门控：** 风格锁定前，不进入 Phase 4 之后的素材/动效阶段。

### Phase 4：出初稿 + 三审

AI 生成第一版完整页面后，人必须做三审。使用 `references/checklists.md` 中的清单逐项检查。

**三审内容：**
1. **内容审**：数据、逻辑、重点对不对？
2. **视觉审**：风格统一吗？信息层级清晰吗？
3. **体验审**：观众的眼睛会先看哪里？节奏对吗？

**退出标准：** 用户确认三审通过，或记录明确的修改项。

### Phase 5：自动补素材，但给约束

让 AI 判断哪些页面需要什么素材，但要给明确约束：

- logo 保持官方原貌，别改颜色
- 截图尺寸一致，风格统一
- 不要每页都堆素材，只加真正有助于表达的
- 素材必须标注来源或生成方式

**每增加一个素材都要问：** 这个素材让信息更好懂吗？

**退出标准：** 用户确认素材清单和约束。

### Phase 6：只在必要处加图表/动效 + 输出

**图表/动效判断标准：**
- 图表：呈现对比、趋势、结构，让观众一眼看到重点
- 3D/插画：营造氛围、强化主题感，不要每页都加
- 动效：控制信息节奏，比如一页内容分步出现

**判断问题：** 加了之后，信息是不是更好懂？如果不是，就不加。

**输出格式建议：**
- 在线演示 → 网页/HTML
- 正式汇报 → PPTX
- 存档或打印 → PDF

**退出标准：** 用户明确输出格式和最终检查项。

## 门控规则（CRITICAL）

1. **内容 outline 锁定前，不出视觉风格建议。**
2. **风格锁定前，不进入素材 / 动效。**
3. **每增加一个素材 / 图表 / 动效，必须回答：加了之后信息是否更好懂？**
4. **最终精修必须有人参与，AI 不替代最终判断。**

## 输出文件

根据用户需要，可在工作目录创建以下 markdown 文件：

| 文件 | 内容 | 何时创建 |
|------|------|----------|
| `ppt_outline.md` | 逐页文字稿 | Phase 2 锁定后 |
| `ppt_style_report.md` | 风格推荐与选定理由 | Phase 3 锁定后 |
| `ppt_review_checklist.md` | 三审检查清单及结果 | Phase 4 完成后 |

这些文件仅用于记录和协作，**不生成 PPTX**。

## 常见错误

| 错误 | 后果 | 解决 |
|------|------|------|
| 还没定目的就生成页面 | 图文不搭、逻辑不顺 | 必须先完成 Phase 1 |
| 风格换来换去 | 整套 PPT 不统一 | Phase 3 选定后锁定 |
| 每页都堆图表和动效 | 分散注意力 | 用「更好懂？」过滤 |
| 输出格式选错 | 现场播放或后续编辑出问题 | Phase 6 一开始就明确 |
| AI 代替人做最终判断 | 细节经不起推敲 | 人必须完成 Phase 6 精修 |
